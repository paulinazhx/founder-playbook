# The Founder Playbook

A free reference for people doing the founder job — what to build and what to build it
with, how to get to revenue while you are still the only salesperson, and the parts of the
CEO job nobody takes off your hands. Eighteen guides, no gate, no signup.

**Read it at
[paulinazhx.github.io/founder-playbook](https://paulinazhx.github.io/founder-playbook/).**

It is written for the stage where you are the product manager, the salesperson, the
recruiter and the person answering support, and every one of those jobs is being done for
the first time. Each guide takes one decision as it actually presents itself: what breaks
if you get it wrong, the options genuinely on the table as a decision table, a worked
example, a checklist you can act on this week, and the failure modes symptom-first. Where
a guide cites a number, it links the organisation that published it rather than a blog
restating it; where no credible number exists, it says so instead of inventing one.

The library splits three ways, by what you are trying to do rather than by what stage you
are at — because nobody knows which stage they are in, but everybody knows whether they
are trying to ship something, sell something, or run something. Each pillar has one
cornerstone guide carrying the whole argument; the guides underneath it are reference.

[Agentic Fabriq](https://agenticfabriq.com).

## Contributing

Corrections are the most useful contribution, especially to a cited number — a wrong figure
here propagates into somebody's actual decision. Open an issue naming the guide, quoting the
claim, and giving the right answer with a source. The editorial bar every guide is held to
is written down in [CONTRIBUTING.md](CONTRIBUTING.md).

## Local development

The site is a static [Astro](https://astro.build) build published to GitHub Pages. Node 22.

```sh
npm ci
npm run dev        # local preview at http://localhost:4321/founder-playbook/
npm run og         # redraw the social cards after a title change
npm run readme     # regenerate the index in this file
npm run verify     # what CI runs: build, tests, markdown lint, links, cards, this index
```

`npm run verify` is the gate. It refuses to pass on a broken internal link, an orphaned
page, a missing or stale social card, a title or description outside its length bounds, a
guide whose `relatedGuides` names something that does not exist, or an index in this file
that has drifted from the content. External links, including every citation, are checked
separately with `npm run check:links:external`, which is deliberately not part of `verify`
— gating a deploy on third-party servers trades a real failure for a theoretical one.
